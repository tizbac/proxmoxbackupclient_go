**Proxmox Backup Client هو عميل نسخ احتياطي مفتوح المصدر (GPL-3.0) لخادم بروكسموكس للنسخ الاحتياطي (PBS)، ويعمل على ويندوز ولينكس.**
إنه **مجموعة أدوات** للنسخ الاحتياطي إلى PBS:

- **Proxmox Backup Client GUI** (المبني على واجهة Nimbus Backup GUI من RDEM Systems) — واجهة رسومية حديثة للنسخ الاحتياطي لخوادم ومحطات عمل ويندوز إلى PBS: لقطات VSS متسقة، مهام مجدولة، وضعا الملفات والأقراص، تصفح/استعادة اللقطات، دعم عدة خوادم PBS ووضع خدمة ويندوز.
- **`proxmoxbackup-directory`** — أداة سطر أوامر لنسخ احتياطي للمجلدات (PXAR) مع إزالة التكرار.
- **`proxmoxbackup-machine`** — أداة سطر أوامر لنسخ احتياطي كامل مباشر لأنظمة ويندوز (FIDX، VSS، تزايدي).
- **`proxmoxbackup-nbd`** — خادم NBD لاستعادة نسخ الأقراص الاحتياطية (لينكس).

> الكلمات المفتاحية: عميل بروكسموكس للنسخ الاحتياطي ويندوز · عميل PBS · نسخ احتياطي VSS لنظام ويندوز · نسخ احتياطي خارجي غير قابل للتعديل · واجهة خادم بروكسموكس للنسخ الاحتياطي.

### استثناءات نظام ذكية (وضع الملفات)
عند نسخ قرص كامل (مثل `D:\`)، يستبعد Proxmox Backup Client تلقائيًا:

**مجلدات النظام:** `System Volume Information` (تخزين VSS، قد يصل إلى 100+ غيغابايت)، `$RECYCLE.BIN`، `Recovery`.
**ملفات النظام:** `pagefile.sys`، `hiberfil.sys`، `swapfile.sys`.

**لماذا هذا مهم:** قد يظهر قرص بمقدار 1.03 تيرابايت مستخدمة بينما الملفات الحقيقية تبلغ ~141 غيغابايت. بدون الاستثناءات، سيتضمن النسخ لقطات VSS (هدر في المساحة والوقت)؛ ومعها، يتطابق الحجم مع البيانات الحقيقية.

**توصية:** استخدم **وضع الملفات** (الافتراضي) مع الاستثناءات التلقائية للنسخ على مستوى الملفات؛ واستخدم **وضع الأقراص** في مهمة منفصلة للاستعادة الشاملة (يتضمن كل شيء).

- منطق إعادة المحاولة مع التراجع الأسي

## 🚀 بدء سريع

1. حمّل `ProxmoxBackupClient.exe` (أو `.msi`) من الإصدارات
2. شغّله بصلاحيات المسؤول (مطلوب لـ VSS)
3. قم بإعداد اتصال PBS واختبره
4. حدد المجلدات المراد نسخها
5. ابدأ النسخ الاحتياطي

## 📋 المتطلبات

- ويندوز 10/11 (64 بت)

## 🔧 الاستخدام المتقدم والأدلة

### عدة PBS (خوادم PBS متعددة)

قم بإعداد عدة خوادم PBS واختر الهدف لكل نسخة (مثل `C:\Users` → PBS سريع SSD، يوميًا؛ `C:\` → PBS للبيانات الضخمة، أسبوعيًا؛ بالإضافة إلى خادم تعافٍ من الكوارث DR).

- **[دليل المستخدم](MULTI_PBS_USER_GUIDE.md)** — إضافة/اختبار الخوادم، الخادم الافتراضي، الأسئلة الشائعة واستكشاف الأخطاء.
- **[دليل التنفيذ](MULTI_PBS_GUIDE.md)** — نموذج البيانات، الترحيل التلقائي من إعداد PBS أحادي، طرق API الخلفية.

يُرحّل إعداد PBS الأحادي الموجود تلقائيًا إلى خادم `default` عند أول تحميل.

### ISO Clonezilla (استعادة شاملة bare-metal)

يُبنى سير عمل الإنقاذ عبر ترميم ISO Clonezilla Live مع الملفات التنفيذية `pbsnbd` / `machinebackup` وإدخال **pbs-nbd** في القائمة الرئيسية لـ Clonezilla (إقلاع من CD، USB عبر `dd`، وUEFI):

```bash
./patch-clonezilla.sh \
  -o clonezilla-live-patched.iso \
  clonezilla-live-3.3.3-15-amd64.iso \
  ./build/pbsnbd ./build/machinebackup \
  ./clonezilla-patch/ocs-pbs-nbd
```

التفاصيل الكاملة (لماذا إعادة بناء كاملة للـ ISO بدلًا من الاستبدال في المكان، المتطلبات، تدفق القائمة، التحقق) في **[PATCH-CLONEZILLA.md](PATCH-CLONEZILLA.md)**.

### بناء واجهة ويندوز للـ GUI

**Docker (موصى به، خاصة عند البناء على لينكس).** ينتج النص البرمجي بأمر واحد ملف `ProxmoxBackupClientGO.exe` بدعم WebView2 مناسب، عبر حاوية `golang` مؤقتة (تثبيت mingw + Wails، بناء الواجهة الأمامية، تنفيذ `wails build`):

```bash
./build_gui_windows_docker.sh
```

**ويندوز أصلي (Chocolatey).** انظر **[BUILD.md](BUILD.md)** للإعداد الكامل لأدوات ويندوز:

```powershell
choco install go
choco install mingw
# ثم، في shell غير مرفوع الصلاحيات:
build.bat          # GUI
build_cli.bat      # CLI
```

أصبحت الواجهة الرسومية مكتملة الآن، لكن المساهمات لا تزال مرحبًا بها، خاصة:

4. تصحيح من طرف Proxmox لإضافة نوع آخر من المدخلات إلى صيغة pxar مع واصفات أمان ويندوز
5. دعم الروابط الرمزية لنظام ويندوز
6. أي شيئ مثير للاهتمام يخطر ببالك :)
