**Proxmox Backup Client — это клиент резервного копирования с открытым исходным кодом (GPL-3.0) для Proxmox Backup Server (PBS), работающий на Windows и Linux.**
Это **набор инструментов** для резервного копирования в PBS:

- **Proxmox Backup Client GUI** (на основе GUI Nimbus Backup от RDEM Systems) — современный графический интерфейс для резервного копирования серверов и рабочих станций Windows в PBS: согласованные снимки VSS, запланированные задания, режимы файлов и дисков, просмотр/восстановление снимков, поддержка нескольких PBS и режим службы Windows.
- **`proxmoxbackup-directory`** — инструмент командной строки для резервного копирования каталогов (PXAR) с дедупликацией.
- **`proxmoxbackup-machine`** — инструмент командной строки для полного резервного копирования работающей системы Windows (FIDX, VSS, инкрементальный).
- **`proxmoxbackup-nbd`** — NBD-сервер для восстановления резервных копий дисков (Linux).

### Умные системные исключения (режим файлов)
При резервном копировании всего диска (например, `D:\`) Proxmox Backup Client автоматически исключает:

**Системные папки:** `System Volume Information` (хранилище VSS, может достигать 100+ ГБ), `$RECYCLE.BIN`, `Recovery`.
**Системные файлы:** `pagefile.sys`, `hiberfil.sys`, `swapfile.sys`.

**Почему это важно:** диск может показывать 1,03 ТБ занятого места, тогда как реальные файлы составляют ~141 ГБ. Без исключений резервная копия включала бы снимки VSS (потраченные зря место и время); с ними размер соответствует реальным данным.

**Рекомендация:** используйте **режим файлов** (по умолчанию) с автоматическими исключениями для резервного копирования на уровне файлов; используйте **режим дисков** в отдельном задании для восстановления bare-metal (включает всё).

## 🚀 Быстрый старт

1. Скачайте `ProxmoxBackupClient.exe` (или `.msi`) из релизов
2. Запустите его с правами администратора (требуется для VSS)
3. Настройте подключение к PBS и проверьте его
4. Выберите папки для резервного копирования
5. Запустите резервное копирование

## 🔧 Расширенное использование и руководства

### Несколько PBS (несколько серверов PBS)

Настройте несколько серверов PBS и выбирайте цель для каждой резервной копии (например, `C:\Users` → быстрый SSD PBS, ежедневно; `C:\` → PBS для больших данных, еженедельно; плюс DR-сервер).

- **[Руководство пользователя](MULTI_PBS_USER_GUIDE.md)** — добавление/тестирование серверов, сервер по умолчанию, FAQ и устранение неполадок.
- **[Руководство по реализации](MULTI_PBS_GUIDE.md)** — модель данных, автоматическая миграция из конфигурации с одним PBS, методы backend API.

Существующая конфигурация с одним PBS автоматически переносится на сервер `default` при первой загрузке.

### ISO Clonezilla (восстановление bare-metal)

Рабочий процесс восстановления создаётся путём модификации ISO Clonezilla Live с помощью бинарных файлов `pbsnbd` / `machinebackup` и записи **pbs-nbd** в главное меню Clonezilla (загрузка с CD, USB через `dd` и UEFI):

```bash
./patch-clonezilla.sh \
  -o clonezilla-live-patched.iso \
  clonezilla-live-3.3.3-15-amd64.iso \
  ./build/pbsnbd ./build/machinebackup \
  ./clonezilla-patch/ocs-pbs-nbd
```

Полные подробности (почему полная пересборка ISO, а не замена на месте, требования, потоки меню, проверка) в **[PATCH-CLONEZILLA.md](PATCH-CLONEZILLA.md)**.

### Сборка Windows GUI

**Docker (рекомендуется, особенно при сборке под Linux).** Скрипт одной командой создаёт `ProxmoxBackupClientGO.exe` с надлежащей поддержкой WebView2, используя одноразовый контейнер `golang` (установка mingw + Wails, сборка фронтенда, выполнение `wails build`):

```bash
./build_gui_windows_docker.sh
```

**Нативный Windows (Chocolatey).** См. **[BUILD.md](BUILD.md)** для полной настройки инструментов Windows:

```powershell
choco install go
choco install mingw
# затем, в не повышенной оболочке:
build.bat          # GUI
build_cli.bat      # CLI
```
