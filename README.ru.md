**Proxmox Backup Client: клиент резервного копирования с открытым исходным кодом (GPL-3.0) для Proxmox Backup Server (PBS), для Windows и Linux.** Он создаёт резервные копии папок в виде архивов файлов, которые можно просматривать, и целых машин в виде загрузочных образов дисков, по расписанию или по запросу. Он восстанавливает что угодно, от одного файла до целой машины: на тот же компьютер, на компьютер-замену или в виртуальную машину Proxmox VE.

Это **набор инструментов**:

- **Proxmox Backup Client GUI** (создан RDEM Systems как Nimbus Backup GUI, переработан и расширен mjb-is): приложение для Windows и Linux. Наборы резервного копирования с несколькими расписаниями у каждого, резервные копии папок и целых дисков с согласованными снимками (VSS в Windows, elastio-snap/dattobd в Linux), восстановление файлов из копий папок и машин, **Undelete** (восстановление удалённых файлов) и **Roll back** (откат), несколько серверов PBS, шифрование на стороне клиента и фоновая служба, благодаря которой расписания выполняются, даже когда никто не вошёл в систему.
- **`proxmoxbackup-directory`**: резервное копирование папок (pxar) из командной строки, с дедупликацией и обнаружением изменений.
- **`proxmoxbackup-machine`**: «живое» резервное копирование целых дисков (fidx) машин Windows и Linux из командной строки. После восстановления образ загрузочный.
- **`proxmoxbackup-nbd`**: подключает резервную копию диска как блочное устройство NBD (Linux).
- **ISO для восстановления на «голое железо» (bare-metal)** на основе Clonezilla Live, с пошаговым восстановлением от включения питания до перезагрузки.

## 🆕 Новое в версии 2.0

Версия 2.0 вносит в проект большой объём работы над графическим интерфейсом, фоновой службой и движком резервного копирования (см. [CHANGELOG](CHANGELOG.md)). По сравнению с 1.2:

- **Приложение подключается к фоновой службе с правами администратора.** Когда служба установлена, серверы PBS и наборы резервного копирования (**Backup Sets**) компьютера принадлежат службе, и только служба читает свою папку настроек. Приложение один раз запрашивает права администратора для подключения (UAC в Windows, pkexec в Linux; на стандартной учётной записи нужны имя и пароль администратора). С повышенными правами работает только небольшой вспомогательный модуль, а токен службы приложение хранит только в памяти. Пользователь, который не может ответить на запрос, может выбрать **Use my own settings** (использовать мои собственные настройки) и сохранить свои серверы и наборы, которые выполняются, пока приложение открыто; **Connect** (подключиться) позже предложит скопировать их в настройки компьютера. Само приложение работает без прав администратора и предлагает **Restart as administrator** (перезапустить от имени администратора) там, где операции это нужно. См. раздел 15 [руководства по графическому интерфейсу](docs/manual/GUI.md#connecting-to-the-background-service).
- **Приложение проверяет, что общается именно со службой.** Прежде чем отправить что-либо в локальный API службы, приложение проверяет, кто отвечает: собственный процесс службы в Windows, сокет, принадлежащий root, в Linux. Программа, которая заняла порт, пока служба остановлена, ничего не получит.
- **Наборы резервного копирования с несколькими расписаниями у каждого**, от каждых нескольких минут до раза в год (последний день месяца, 2-й вторник), каждое описано простыми словами с ближайшими 3 запусками.
- **Инкрементальные копии папок** с обнаружением изменений как в официальном клиенте (режимы **Data** (данные) и **Metadata** (метаданные)): неизменённые файлы повторно не читаются.
- **Более быстрые копии машин**, которые пропускают свободное место, файл подкачки и файл гибернации и записывают нечитаемые секторы нулями вместо того, чтобы завершаться ошибкой.
- **Несколько резервных копий одновременно** (**Maximum Concurrent Backups** (максимум одновременных копий), от 1 до 8, по умолчанию 3), в том числе в фоновой службе, у каждой свой снимок, свой журнал, **Pause** (пауза) и **Stop** (остановить).
- **Ограничения скорости** для отправки в PBS, загрузки из PBS и чтения с диска; каждое ограничение является общим бюджетом для всего, что выполняется одновременно.
- **Undelete и Roll back** для наборов копий папок и машин, в графическом интерфейсе и из командной строки.
- **Файлы из копий машин**: просмотр томов NTFS, FAT, exFAT, ext2/3/4 и XFS внутри образа диска и восстановление отдельных файлов.
- **Ключи шифрования, которые можно сохранить**: сохранение копии, печать бумажного ключа с QR-кодом и импорт ключа из файла, с камеры, с фотографии или из введённого текста.
- **Наборы копий машин привязывают диски по их идентификатору**, поэтому диск, получивший новый номер после замены оборудования, по-прежнему остаётся тем, что копируется, а отсутствующий диск приводит к ошибке запуска вместо копирования другого диска.
- **Разделы можно исключить из копии машины**: отметьте под каждым диском разделы, которые нужно копировать. Исключённый раздел не читается и не попадает в снимок, а в образ записывается нулями, поэтому при восстановлении он возвращается на своё место и в своём размере, пустой и неотформатированный. Выбор дисков отмечает разделы, которые нужны восстановленному диску для загрузки.
- **Копии машин Linux с elastio-snap или dattobd.** Набор машины Linux может отключить снимки и читать диски «вживую», но только если владелец отметит, что согласен с возможной несогласованностью копии.
- **Каждый пользователь может выбрать свою цветовую тему** в приложении без бренда. Приложение с брендом сохраняет цвета своего бренда.
- **Включение и отключение набора резервного копирования** как из его редактора, так и из его меню, а также предупреждение при сохранении, если набор не будет выполняться в сохранённом виде (отключён, нет включённого расписания, проблема со снимком, отсутствует диск).
- **Пакеты для Linux** (`.deb`, `.rpm` и Arch), имя пакета и службы `proxmoxbackupclient`, вместе с фоновой службой.
- **Пошаговый ISO для восстановления bare-metal**, который также восстанавливает в пустую виртуальную машину (P2V). Машину, скопированную как виртуальная машина Proxmox VE, также можно восстановить прямо из PBS в Proxmox VE, как любую ВМ, которую скопировал сам Proxmox VE.
- **Брендированные сборки**: одни и те же исполняемые файлы поставляются как установщики Proxmox Backup Client, Nimbus Backup, Acme Backup и Etitech Backup.
- **18 языков интерфейса.**

### 🔎 Проверка любой загрузки

Каждый выпуск содержит контрольные суммы SHA-256 (`SHA256SUMS.txt`, они также приведены на странице выпуска) и **подписанное подтверждение происхождения** (attestation): криптографическое доказательство того, что файл собран CI этого репозитория из конкретного коммита.

```powershell
Get-FileHash .\ProxmoxBackupClient-<version>.msi -Algorithm SHA256   # compare with SHA256SUMS.txt
gh attestation verify .\ProxmoxBackupClient-<version>.msi --repo tizbac/proxmoxbackupclient_go
```

В Linux: `sha256sum -c SHA256SUMS.txt --ignore-missing`.

Если установщики выпуска чисто проходят проверку VirusTotal, на странице выпуска есть ссылки на отчёты.

> ℹ️ **Подпись кода:** исполняемые файлы для Windows **пока не подписаны Authenticode** (сертификат OSS через [SignPath Foundation](https://signpath.org) ожидается). До тех пор происхождение подтверждается приведёнными выше подтверждением и контрольными суммами.

## 🚀 Быстрый старт (графический интерфейс)

1. Установите: MSI в Windows, пакет `.deb`, `.rpm` или Arch в Linux ([Загрузка](#-download)).
2. Запустите **Proxmox Backup Client**. Установщики настраивают фоновую службу, поэтому приложение один раз запрашивает права администратора для подключения к ней (UAC в Windows, ваш пароль через pkexec в Linux). Если вы не можете их предоставить, выберите **Use my own settings** (использовать мои собственные настройки).
3. Добавьте свой сервер PBS в **Preferences > Account Information** (настройки > данные учётной записи) и нажмите **Test** (проверить).
4. Создайте набор резервного копирования (**Backup Set**) или разовую копию и выберите папки или диски для копирования.
5. Запустите его. С фоновой службой его расписания выполняются независимо от того, вошёл ли кто-нибудь в систему.

[Руководство по графическому интерфейсу](docs/manual/GUI.md) подробно описывает каждый шаг.

### 🪟 Автоматическая / тихая установка (MSI)

MSI поддерживает стандартный ключ тихой установки Windows Installer, а также публичные свойства для каждого значения по умолчанию:

```powershell
# Silent install with the defaults (service: Automatic + started)
msiexec /i ProxmoxBackupClient-<version>.msi /quiet

# Silent install that installs the service but does NOT enable/autostart it
# (created as Manual and left stopped)
msiexec /i ProxmoxBackupClient-<version>.msi /quiet SERVICEAUTOSTART=0

# Silent install that also applies a settings file exported from another computer
msiexec /i ProxmoxBackupClient-<version>.msi /quiet CONFIGFILE="C:\Deploy\settings.json"

# Custom directory + verbose install log
msiexec /i ProxmoxBackupClient-<version>.msi /quiet INSTALLFOLDER="D:\Apps\ProxmoxBackupClient" /L*v "C:\Temp\install.log"

# Silent uninstall (KEEP_CONFIG=0 also purges %ProgramData%\<name>)
msiexec /x ProxmoxBackupClient-<version>.msi /quiet KEEP_CONFIG=0
```

| Свойство | По умолчанию | Значение |
| --- | --- | --- |
| `SERVICEAUTOSTART` | `1` | `0` = служба устанавливается с типом запуска **Manual** (вручную) и остаётся **остановленной**: установлена, но не включена и не запускается автоматически |
| `AUTOSTART` | `1` | `0` = не запускать приложение в области уведомлений при входе каждого пользователя |
| `DESKTOPSHORTCUTS` | `1` | `0` = без ярлыка на рабочем столе (пункт в меню «Пуск» добавляется всегда) |
| `CONFIGFILE` | | Полный путь к файлу, сохранённому через **Preferences > Export Settings** (настройки > экспорт настроек): его серверы PBS и наборы резервного копирования объединяются с текущими до запуска службы. Идентификаторы копий (Backup ID), образованные от имени экспортировавшего компьютера, образуются от имени каждого компьютера. См. [installer/DEPLOYMENT.md](installer/DEPLOYMENT.md) |
| `KEEP_CONFIG` | `1` | Только при удалении: `0` = также удалить каталог состояния `%ProgramData%\<name>` |
| `INSTALLFOLDER` | `Program Files` | Каталог установки (его можно изменить и в интерфейсе установщика) |

Запускайте с повышенными правами (администратор); код выхода `0` = успех, `3010` = успех + требуется перезагрузка. Брендированные MSI принимают точно такие же ключи.

### Инструменты командной строки
- `proxmoxbackup-directory`: копии папок (pxar) с дедупликацией и `-change-detection-mode legacy|data|metadata`
- `proxmoxbackup-machine`: «живые» копии целых дисков машин Windows (VSS) и Linux (elastio-snap/dattobd) (fidx, инкрементально, свободное место пропускается, если не указан `-readfreespace`, `-type vm` для копии Proxmox VE, `-skippartition <disk>:<number>` чтобы исключить раздел)
- `proxmoxbackup-nbd`: NBD-сервер для восстановления копий дисков (Linux)
- `ProxmoxBackupClientSVC` (Windows) и `proxmoxbackupclient` (пакеты Linux): `-list-sets`, `-undelete` и `-rollback` для наборов резервного копирования, заданных в графическом интерфейсе

Первые три принимают `-keyfile` и `-keyfile-passphrase` для зашифрованных снимков. Полный справочник: [руководство по командной строке](docs/manual/CLI.md).

### Умные системные исключения (копии папок)
Копии папок сами пропускают следующее:

**Системные папки:** `System Volume Information` (хранилище VSS, может занимать более 100 GB) и `$RECYCLE.BIN`, где бы они ни находились; `Recovery` только в корне диска; `.pbs-rollback` (страховочная папка функции **Roll back** (откат)).
**Системные файлы:** `pagefile.sys`, `hiberfil.sys`, `swapfile.sys` и `DumpStack.log.tmp`.

**Почему это важно:** диск может показывать 1,03 TB занятого места, тогда как реальные файлы занимают ~141 GB. Без исключений копия включала бы снимки VSS (потеря места и времени); с ними размер соответствует реальным данным.

**Рекомендация:** используйте копию **папок** для резервного копирования на уровне файлов; используйте копию **машины** в отдельном наборе резервного копирования для восстановления bare-metal и P2V (образ целого диска, в который свободное место, файлы подкачки и гибернации записываются нулями).

### Безопасность и качество
- Папка настроек службы доступна только SYSTEM и Administrators (Windows) или только root (Linux); её локальный API слушает на 127.0.0.1 и требует токен, который заменяется при каждом запуске и каждые 24 часа
- Приложение ничего не отправляет в этот API, пока не проверит, что отвечает сама служба (процесс службы в Windows, сокет, принадлежащий root, в Linux)
- В Windows токены и пароли PBS в `config.json` зашифрованы для данного компьютера (DPAPI)
- Проверка входных данных, очистка учётных данных, защита от обхода путей (path traversal), повторы с экспоненциальной задержкой
- Модульные тесты в каждом модуле, а также необязательные живые тесты и сквозные тесты с реальным PBS

## 🔐 Шифрование на стороне клиента

Снимки можно зашифровать до того, как они покинут машину, с помощью файла ключа Proxmox Backup Server (в формате, который записывает `proxmox-backup-client key create`, поэтому ключи взаимозаменяемы с официальным клиентом). Каждый блок шифруется AES-256-GCM, а манифест подписывается. Сервер PBS никогда не видит ключ.

**Графический интерфейс:** откройте **Preferences > Account Information** (настройки > данные учётной записи), измените сервер и перейдите на его вкладку **Encryption** (шифрование). Кнопкой **Import...** (импорт) загрузите уже имеющийся ключ (копию файла ключа или бумажный ключ, считанный камерой, со скана или фото, либо введённый вручную) или кнопкой **Generate...** (создать) создайте новый. На вкладке показан отпечаток ключа. **Save a copy...** (сохранить копию) и **Print a paper key...** (напечатать бумажный ключ, с QR-кодом) позволяют хранить копию вдали от компьютера. Отчёты показывают, была ли зашифрована каждая копия. **Без файла ключа снимок восстановить невозможно: храните копию в надёжном месте, вдали от этой машины.**

**Ключи, защищённые парольной фразой (scrypt или PBKDF2):** **Ask me** (спрашивать меня) хранит парольную фразу в памяти в течение одного сеанса приложения; **Remember on this computer** (запомнить на этом компьютере) сохраняет её так же, как токен PBS, и подходит для расписаний и фоновой службы.

**Командная строка:**
```shell
proxmoxbackup-directory.exe -baseurl ... -backupdir "C:\data" -datastore store -keyfile "C:\keys\pbs-key.json" -keyfile-passphrase "..."
```
`-keyfile-passphrase` (или `PBS_ENCRYPTION_PASSWORD`) нужен только для защищённого ключа и запрашивается, если не указан. `proxmoxbackup-machine` и `proxmoxbackup-nbd` принимают те же флаги. `proxmoxbackup-nbd` проверяет ключ по снимку до обращения к устройству NBD, поэтому неверный ключ сразу приводит к ошибке.

**Восстановление bare-metal:** ISO для восстановления запрашивает ключ (без ключа, файл ключа на USB-флешке или введённый путь) и парольную фразу защищённого ключа. Ключ никогда не записывается в ISO.

Для восстановления зашифрованного снимка нужен тот же файл ключа; если он утерян, восстановить данные невозможно.

## Более быстрые копии папок: обнаружение изменений

В режиме по умолчанию **Legacy** (классический) каждая копия папок читает каждый файл, поэтому запуск длится столько же, сколько чтение всей папки, даже если ничего не изменилось. Наборы резервного копирования и `proxmoxbackup-directory` могут вместо этого использовать режимы обнаружения изменений официального `proxmox-backup-client`:

| Режим | Что читает | Как хранится |
|---|---|---|
| **Legacy** (по умолчанию) | каждый файл | один `<name>.pxar.didx` на папку |
| **Data** (данные) | каждый файл | разделённый архив: `<name>.mpxar.didx` (метаданные) + `<name>.ppxar.didx` (содержимое файлов) |
| **Metadata** (метаданные) | только новые и изменённые файлы | тот же разделённый архив; файлы, у которых размер, время изменения (с точностью до наносекунды), режим доступа и владелец совпадают с предыдущей копией, берутся из неё без чтения |

В режиме **Metadata** первый запуск читает всё; последующие читают только изменённое. Файл, изменённый так, что его размер и время изменения остались прежними, не будет замечен, поэтому набор также может **читать все файлы каждые N запусков** (параметр **Read every file every**). Дайте каждому набору резервного копирования собственный идентификатор копии (Backup ID): режим **Metadata** сравнивает с самым новым снимком в группе копий. В командной строке используйте `-change-detection-mode`.

**Прежде чем переводить набор в режим Data или Metadata,** обновите до 2.0 каждую машину, на которую вы восстанавливаете: более ранние версии показывают папки разделённого архива без их файлов. См. [раздел 7 руководства по графическому интерфейсу](docs/manual/GUI.md#7-incremental-folder-backups-change-detection).

## 🔄 Физические машины в виртуальные (P2V)

Копию машины физического ПК или сервера можно превратить в виртуальную машину Proxmox VE двумя способами:

1. **Восстановить её в Proxmox VE.** Установите для набора резервного копирования (или разовой копии) **Backup as: Proxmox VE virtual machine** (копировать как: виртуальная машина Proxmox VE). Копия хранится как `vm/<number>`, поэтому Proxmox VE показывает её вместе с другими копиями ВМ и восстанавливает как ВМ (один диск SATA; перед запуском добавьте сетевую карту).
2. **Восстановить её с помощью ISO для восстановления в пустую ВМ** с той же прошивкой, что у исходной машины, диском SATA не меньшего размера и сетевой картой Intel E1000. Это работает одинаково для копий `host` и `vm`, а ту же копию по-прежнему можно восстановить на «голое железо».

Проверенные варианты включают Windows 10 и Windows Server (UEFI/GPT), настольные Linux (UEFI/GPT и BIOS/MBR) и зашифрованную копию Linux с ключом на USB-флешке. В [руководстве по восстановлению bare-metal](docs/manual/BMR.md#7-restoring-onto-different-hardware-p2v-and-replacement-machines) есть полная таблица, варианты прошивки, драйверы и пошаговые инструкции.

## 🤝 Совместим с официальным клиентом Proxmox в обоих направлениях

Проверено с `proxmox-backup-client` 3.4.9 и PBS 4.2:

- **Снимки Legacy, Data и Metadata, созданные этим клиентом, восстанавливаются официальным клиентом байт в байт**, как из графического интерфейса, так и из командной строки, созданные в Windows или Linux, а файловый браузер PBS 4.2 их открывает.
- **Снимки Legacy, Data и Metadata, созданные официальным клиентом, восстанавливаются этим клиентом байт в байт**, полностью или выборочно.
- Тот же формат разделённого архива (pxar версии 2), те же режимы обнаружения изменений, тот же формат файла ключа шифрования, те же переменные окружения в стиле `PBS_REPOSITORY`.

Ваши копии никогда не привязаны к этому клиенту. Единственное дополнение: небольшой файл в корне снимка папки, `.proxmox_backup_client_meta.json` (исходный путь), который официальный клиент восстанавливает как обычный файл.

## «Живое» резервное копирование всей машины

`proxmoxbackup-machine` (и копии машин в графическом интерфейсе) копирует целую систему Windows 10/11 или Windows Server либо машину Linux без какого-либо простоя.

Синтаксис команды в основном такой же, как для копий папок, только `-backupdir` заменяется на `-backupdev` (повторите его для нескольких дисков). Например:

`proxmoxbackup-machine.exe -authid yourapikey -backupdev \\.\PhysicalDrive0 -baseurl https://yourpbs:8007 -certfingerprint xx:xx:xx... -datastore zfs -secret L4m3r -backup-id testfull1`

Эта команда просматривает диск 0, находит все смонтированные разделы, создаёт их снимок VSS, а затем создаёт загрузочный образ всего диска в формате fidx. Свободное место, файлы подкачки и гибернации записываются в образ нулями без чтения (в Linux также свободное место ext2/3/4 и XFS); `-readfreespace` вместо этого читает всё, для криминалистической копии. Сектор, который не удаётся прочитать, записывается в образ нулями, и запуск сообщает, где это произошло. Добавьте `-type vm` (с числовым `-backup-id`), чтобы сохранить копию как копию ВМ Proxmox VE ([P2V](#-physical-machines-into-virtual-machines-p2v)).

Следующая копия инкрементальная. Хеширование распараллелено, поэтому можно достичь скорости 1 GB/s.

Чтобы исключить раздел, например библиотеку игр или раздел данных, уже покрытый копией папок, добавьте `-skippartition <disk>:<number>` (повторите для нескольких), например `-skippartition \\.\PhysicalDrive0:4` или `-skippartition /dev/sda:3`. Раздел не читается и не попадает в снимок, а в образ записывается нулями: таблица разделов сохраняется, поэтому при восстановлении раздел возвращается на своё место и в своём размере, пустой и неотформатированный. В графическом интерфейсе снимите отметку с раздела под его диском в наборе резервного копирования.

### Требования для копий машин Linux (аналог VSS)

Копирование машин Windows использует VSS. В Linux нет VSS, поэтому для копии работающей машины Linux нужен модуль ядра `elastio-snap` (форк `dattobd`), чтобы сделать снимок блочного устройства на определённый момент, пока на него идёт запись. Сам `dattobd` тоже работает, если он уже загружен.

Исходный репозиторий `elastio/elastio-snap` заархивирован и больше не собирается на современных ядрах. Используйте поддерживаемый форк [`Axcient/elastio-snap`](https://github.com/Axcient/elastio-snap) (ветка `develop`). Версия 0.12.11 этого форка собралась и работала на Debian 13 с ядром 6.12. Пакет `.deb` рекомендует пакет `elastio-snap-dkms`.

Необходимы два условия, иначе копия машины Linux откажется запускаться:

1. **Модуль ядра должен быть установлен и загружен.** Сборка из исходного кода:
   ```bash
   sudo apt-get install linux-headers-$(uname -r) build-essential   # Debian/Ubuntu
   git clone --depth 1 https://github.com/Axcient/elastio-snap.git
   cd elastio-snap
   sudo make
   sudo make install
   sudo depmod -a      # `make install` does not run depmod, and modprobe fails without it
   sudo modprobe elastio-snap
   lsmod | grep elastio_snap
   ```
   Так модуль загружается только до следующей перезагрузки. Добавьте запись в `/etc/modules-load.d/`, чтобы он загружался при каждой загрузке. Его собственный [INSTALL.md](https://github.com/Axcient/elastio-snap/blob/develop/INSTALL.md) описывает установку из пакетов.

2. **Копирование должно выполняться от root.** Интерфейс управления модулем доступен только root, и обычному пользователю в снимке отказывается. Фоновая служба работает от root; без неё используйте в приложении **Restart as administrator** (перезапустить от имени администратора) или запускайте `proxmoxbackup-machine` через `sudo`. Обычной копии папок root не нужен.

В графическом интерфейсе набор копии машины Linux может снять отметку **Use snapshots** (использовать снимки) и читать диски «вживую», но только если отмечен второй флажок («Run without a snapshot: I accept the backup may be inconsistent», то есть «выполнять без снимка: я согласен, что копия может быть несогласованной»). Без него каждый запуск останавливается и объясняет причину. Несмонтированные разделы читаются напрямую.

### Восстановление файлов из копии диска

Страница **Restore** (восстановление) графического интерфейса открывает копию машины так же, как копию папок: каждый том в образе (NTFS, FAT, exFAT, ext2/3/4 или XFS) представлен папкой, которую можно просматривать и из которой можно восстанавливать. Ничего не монтируется.

В Linux копию диска можно также подключить как блочное устройство с помощью инструмента nbd. Сначала выполните `modprobe nbd max_part=0`: при `max_part != 0` ядро может бесконечно зациклиться, опрашивая разделы.

Инструмент NBD подключает любую копию диска фиксированного размера, будь то копия VM или host (поэтому он работает и для копий Proxmox VE). Например:

`./proxmoxbackup-nbd -authid 'apikey' -baseurl https://yourpbs:8007 -secret 'yoursecret' -certfingerprint 'aa:...:xx' -datastore test -namespace test1 -path "vm/107/2025-08-02T23:13:01Z/drive-virtio0.img.fidx"`

Если не указать `-path`, текстовый интерфейс в терминале позволит выбрать файл fidx; `-list` вместо этого выводит все образы.

> Не используйте это на машине, где работает что-то важное: повреждённая файловая система может привести к сбою ОС, поэтому Proxmox VE использует для этого экземпляр QEMU.

Перед остановкой `proxmoxbackup-nbd` отмонтируйте всё на диске nbd, иначе раздел, скорее всего, останется занятым. Если вы получили ошибку `Device or resource busy`, принудительно отключитесь командой `nbd-client -d /dev/nbd0` или перезагрузитесь.

### Восстановление на физическую машину или в ВМ

Используйте [ISO для восстановления bare-metal](#-bare-metal-restore-iso), на «голое железо» или в пустую виртуальную машину. [Руководство по восстановлению bare-metal](docs/manual/BMR.md) описывает это шаг за шагом.

## Использование: резервное копирование каталога

Полный справочник с примерами для Windows и Linux, кодами выхода и планированием находится в **[руководстве по командной строке](docs/manual/CLI.md)**. Типичная команда:

```shell
proxmoxbackup-directory.exe -baseurl "https://yourpbshost:8007" -certfingerprint pbsfingerprint -authid "user@realm!apiid" -secret "apisecret" -backupdir "C:\path\to\backup" -datastore "datastorename"
```

```
proxmoxbackup-directory
  -baseurl string            PBS URL, example: https://192.168.1.10:8007
  -certfingerprint string    Certificate fingerprint (asked for interactively when omitted)
  -authid string             API token ID (user@realm!token)
  -secret string             API token secret
  -pbsusername string        PBS user for ticket login (with -pbspassword; overrides -authid/-secret)
  -pbspassword string        Password for -pbsusername (asked for when omitted)
  -datastore string          Datastore name
  -namespace string          Namespace (optional)
  -backup-id string          Backup ID (default: the hostname)
  -backupdir string          Source directory, must not be a symlink; repeat for several
  -change-detection-mode     legacy (default), data or metadata
  -novss                     Do not snapshot the source (VSS on Windows, elastio-snap/dattobd on Linux)
  -keyfile string            PBS encryption key file
  -keyfile-passphrase string Passphrase for a protected key (asked for when omitted)
  -no-mtime                  Record 1970-01-01 as every file and folder time (see below)
  -backupstream string       Back up standard input as <name>.didx instead of a directory
  -pxarout string            Also write the archive to a local file (debugging)
  -mail-host, -mail-port, -mail-username, -mail-password, -mail-insecure,
  -mail-from, -mail-to, -mail-subject-template, -mail-body-template
                             Email report (optional)
  -config string             JSON config file; flags given on the command line override it
```

Также читаются переменные окружения официального клиента `PBS_REPOSITORY`, `PBS_SERVER`, `PBS_PORT`, `PBS_DATASTORE`, `PBS_AUTH_ID`, `PBS_PASSWORD` и `PBS_FINGERPRINT`.

О настройке через JSON см. [config.json.example](config.json.example); заполняйте только нужные поля.

### Несколько каталогов за один запуск

Повторите `-backupdir`, чтобы скопировать несколько каталогов одной командой:

```shell
proxmoxbackup-directory.exe -baseurl "https://yourpbshost:8007" -certfingerprint pbsfingerprint -authid "user@realm!apiid" -secret "apisecret" -datastore "datastorename" -backupdir "C:\Data" -backupdir "D:\Photos"
```

Каждый каталог копируется в собственную группу копий с идентификатором `<backup-id>_<path>` (`-backup-id` по умолчанию равен имени хоста). Поэтому хранение, очистка (pruning) и восстановление рассматривают каждый каталог как независимую серию. Сбой одного каталога не останавливает остальные, а код выхода сообщает об ошибке. `-pxarout` нельзя сочетать с несколькими каталогами, а два каталога, которые получили бы одинаковый идентификатор копии, отклоняются до начала отправки.

В файле конфигурации JSON используйте `"backupdirs": ["C:\\Data", "D:\\Photos"]`. Одиночное поле `"backupdir"` продолжает работать и может сочетаться с `"backupdirs"`. Шифрование работает так же, как для одного каталога: ключ читается один раз, и им шифруется группа копий каждого каталога.

### Исключение времени из архива

Время изменения каждого файла и папки входит в архив, поэтому изменившееся время меняет байты архива, и блоки вокруг этой записи отправляются снова, хотя в них ничего не изменилось. Для большинства данных это разумный компромисс. Но некоторые деревья постоянно «трогают» свои папки, хотя файлы остаются прежними: хранилище, раскладывающее данные по папкам с именами из хеша (`aa/bb/<rest of the hash>`), может только по этой причине при каждом запуске заново отправлять большую часть архива.

`-no-mtime` (`"no-mtime": true` в файле конфигурации JSON) вместо этого записывает 1970-01-01 как время каждого файла и папки, так что новые блоки появляются только при реальном изменении содержимого. Настоящее время нигде не сохраняется: при восстановлении каждый элемент получает дату 1970-01-01. С `-change-detection-mode metadata` читается каждый файл, как в режиме `data`. По умолчанию параметр выключен; используйте его для источника, где время не имеет значения.

### Шаблоны писем

Работает и ретранслятор без авторизации (часто на порту 25): просто не указывайте имя пользователя и пароль. Отправитель может содержать имя (`Backups <backup@example.com>`).

Для темы и текста писем используется [шаблонизатор Go](https://pkg.go.dev/text/template); синтаксис описан в его документации. Доступны следующие переменные:

- `.NewChunks`: количество созданных новых блоков
- `.ReusedChunks`: количество повторно использованных блоков
- `.Datastore`: имя хранилища данных (datastore)
- `.Error`: ошибка, если она есть (`.ErrorStr` даёт её в виде текста, пустого, если ошибки нет)
- `.ReadErrors`: файлы или папки, которые не удалось прочитать; `.ReadErrorCount`: их количество
- `.Hostname`: имя хоста машины
- `.StartTime`: время начала копирования
- `.EndTime`: время окончания копирования
- `.Duration`: продолжительность копирования
- `.FromattedDuration`: отформатированная продолжительность копирования (в коде имя написано именно так)
- `.Success`: true, если копирование завершилось без ошибок и без нечитаемых данных
- `.Partial`: true, если снимок сохранён, но некоторые файлы не удалось прочитать
- `.Status`: `Success`, `Partial` или `Failed`

## Резервное копирование потока

Этот режим копирует поток вместо архива pxar. Например:

```
mysqldump yourdatabase | ./proxmoxbackup-directory -backupstream yourdatabase.sql [other options]
```

Для дедупликации самого потока, например архива tar или дампа SQL, используется разбиение на блоки buzhash.

## Известные проблемы

Включённая антивирусная защита Windows Defender может замедлить копирование примерно до 25% достижимой скорости.

В Windows инструменты командной строки берут блокировку процесса: вторая копия, запущенная во время выполнения первой, выводит «Another backup job is running» и завершается с кодом 2. В Linux такой блокировки нет, поэтому не планируйте два запуска из командной строки на одно и то же время. (Графический интерфейс и фоновая служба безопасно выполняют несколько копий одновременно, см. [Несколько копий одновременно](docs/manual/GUI.md#67-several-backups-at-once).)

### 💿 ISO для восстановления bare-metal

ISO для восстановления представляет собой стандартный ISO Clonezilla Live, дополненный исполняемыми файлами `pbsnbd` / `machinebackup` и двумя пунктами меню. Он загружается с CD, с USB-флешки (записанной через `dd` или с флешки Ventoy), на машинах с UEFI или BIOS:

- **`ocs-pbs-bare-metal-restore`**: первый пункт загрузочного меню, выбранный по умолчанию, **PBS Bare Metal Restore**. Он пропускает вопросы Clonezilla о языке и раскладке клавиатуры и ведёт прямо от учётных данных PBS к завершённому восстановлению: сначала DHCP (запрос статического IP только при неудаче), ключ шифрования с USB-флешки, если копия зашифрована, и определение целевого диска, которое никогда не предлагает флешку, с которой выполнена загрузка. Он одинаково восстанавливает копии Windows и Linux (восстановление выполняется на уровне блоков), на «голое железо» или в пустую ВМ.
- **`ocs-pbs-nbd`**: пункт **pbs-nbd** в собственном меню выбора режима Clonezilla. Он запрашивает параметры подключения к PBS и снимок, подключает его к `/dev/nbd0`, а затем передаёт управление обычному мастеру восстановления дисков Clonezilla, которым вы управляете вручную.

```bash
./patch-clonezilla.sh \
  -o clonezilla-live-patched.iso \
  clonezilla-live-3.3.3-37-amd64.iso \
  ./build/pbsnbd ./build/machinebackup \
  ./clonezilla-patch/ocs-pbs-nbd ./clonezilla-patch/ocs-pbs-bare-metal-restore
```

`make clonezilla` скачивает стандартный ISO и делает то же самое. Все подробности (почему полная пересборка ISO, а не замена на месте, требования, порядок меню, проверка) приведены в **[PATCH-CLONEZILLA.md](PATCH-CLONEZILLA.md)**; использование описано в **[руководстве по восстановлению bare-metal](docs/manual/BMR.md)**.
