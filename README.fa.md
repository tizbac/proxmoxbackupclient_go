**پروکس‌موکس بک‌آپ کلاینت یک کلاینت پشتیبان‌گیری متن‌باز (GPL-3.0) برای سرور پشتیبان‌گیری پروکس‌موکس (PBS) است که روی ویندوز و لینوکس کار می‌کند.**
این یک **مجموعه ابزارها** برای پشتیبان‌گیری به PBS است:

- **Proxmox Backup Client GUI** (بر پایه Nimbus Backup GUI از RDEM Systems) — رابط گرافیکی مدرن برای پشتیبان‌گیری از سرورها و ایستگاه‌های کاری ویندوز به PBS: اسنپ‌شات‌های سازگار با VSS، کارهای زمان‌بندی‌شده، حالت‌های فایل و دیسک، مرور/بازیابی اسنپ‌شات، پشتیبانی چند PBS و حالت سرویس ویندوز.
- **`proxmoxbackup-directory`** — ابزار خط فرمان برای پشتیبان‌گیری از پوشه‌ها (PXAR) با حذف تکرار (deduplication).
- **`proxmoxbackup-machine`** — ابزار خط فرمان برای پشتیبان‌گیری کامل زنده از سیستم‌های ویندوز (FIDX، VSS، افزایشی).
- **`proxmoxbackup-nbd`** — سرور NBD برای بازیابی پشتیبان‌های دیسک (لینوکس).

> کلمات کلیدی: کلاینت پشتیبان‌گیری پروکس‌موکس ویندوز · کلاینت PBS · پشتیبان‌گیری Windows VSS · پشتیبان‌گیری خارج از سایت تغییرناپذیر · رابط سرور پشتیبان‌گیری پروکس‌موکس.

### استثناهای هوشمند سیستم (حالت فایل)
هنگام پشتیبان‌گیری از یک دیسک کامل (مثلاً `D:\`)، Proxmox Backup Client به طور خودکار موارد زیر را استثنا می‌کند:

**پوشه‌های سیستم:** `System Volume Information` (فضای ذخیره‌سازی VSS، می‌تواند به 100+ گیگابایت برسد)، `$RECYCLE.BIN`، `Recovery`.
**فایل‌های سیستم:** `pagefile.sys`، `hiberfil.sys`، `swapfile.sys`.

**چرا اهمیت دارد:** یک دیسک ممکن است 1.03 ترابایت استفاده‌شده نشان دهد در حالی که فایل‌های واقعی حدود 141 گیگابایت هستند. بدون استثناها، پشتیبان شامل اسنپ‌شات‌های VSS می‌شد (اتلاف فضا و زمان)؛ با آن‌ها، اندازه با داده‌های واقعی مطابقت دارد.

**توصیه:** برای پشتیبان‌گیری در سطح فایل از **حالت فایل** (پیش‌فرض) با استثناهای خودکار استفاده کنید؛ برای بازیابی bare-metal (شامل همه‌چیز) از **حالت دیسک** در یک کار جداگانه استفاده کنید.

## 🚀 شروع سریع

1. `ProxmoxBackupClient.exe` (یا `.msi`) را از نسخه‌ها دانلود کنید
2. آن را با حقوق مدیر اجرا کنید (برای VSS لازم است)
3. اتصال PBS خود را پیکربندی و آزمایش کنید
4. پوشه‌هایی را که می‌خواهید پشتیبان بگیرید انتخاب کنید
5. پشتیبان‌گیری را شروع کنید

## 🔧 استفاده پیشرفته و راهنماها

### چند PBS (چندین سرور PBS)

چندین سرور PBS پیکربندی کنید و برای هر پشتیبان هدف را انتخاب کنید (مثلاً `C:\Users` → PBS سریع SSD، روزانه؛ `C:\` → PBS داده‌های حجیم، هفتگی؛ به‌علاوه یک سرور DR).

- **[راهنمای کاربر](MULTI_PBS_USER_GUIDE.md)** — افزودن/آزمایش سرورها، سرور پیش‌فرض، سوالات متداول و عیب‌یابی.
- **[راهنمای پیاده‌سازی](MULTI_PBS_GUIDE.md)** — مدل داده، مهاجرت خودکار از پیکربندی تک‌PBS، روش‌های API بک‌اند.

پیکربندی تک‌PBS موجود در اولین بارگذاری به طور خودکار به سرور `default` منتقل می‌شود.

### ISO کلونزیلا (بازیابی bare-metal)

جریان کار نجات با وصله‌کردن یک ISO زنده کلونزیلا با باینری‌های `pbsnbd` / `machinebackup` و یک ورودی **pbs-nbd** در منوی اصلی کلونزیلا ساخته می‌شود (بوت از CD، USB از طریق `dd` و UEFI):

```bash
./patch-clonezilla.sh \
  -o clonezilla-live-patched.iso \
  clonezilla-live-3.3.3-15-amd64.iso \
  ./build/pbsnbd ./build/machinebackup \
  ./clonezilla-patch/ocs-pbs-nbd
```

جزئیات کامل (چرا بازسازی کامل ISO به جای تعویض درجا، پیش‌نیازها، جریان منو، تأیید) در **[PATCH-CLONEZILLA.md](PATCH-CLONEZILLA.md)**.

### ساخت GUI ویندوز

**Docker (توصیه‌شده، به‌ویژه هنگام ساخت روی لینوکس).** اسکریپت تک‌فرمانی یک `ProxmoxBackupClientGO.exe` با پشتیبانی مناسب WebView2 تولید می‌کند، با استفاده از یک کانتینر `golang` یک‌بارمصرف (نصب mingw + Wails، ساخت فرانت‌اند، اجرای `wails build`):

```bash
./build_gui_windows_docker.sh
```

**ویندوز بومی (Chocolatey).** برای راه‌اندازی کامل ابزارهای ویندوز به **[BUILD.md](BUILD.md)** مراجعه کنید:

```powershell
choco install go
choco install mingw
# سپس، در شل بدون بالابردن مجوز:
build.bat          # GUI
build_cli.bat      # CLI
```
